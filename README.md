## How I practice

1. Understand the problem and constraints.
2. Try an initial solution before looking up optimizations.
3. Explore alternative approaches when useful.
4. Record the time/space trade-offs and lessons learned.

The aim is **consistent improvement and clear reasoning**, not a perfect-looking contribution graph.

## Running solutions

These files use LeetCode-style entry points. For example, the Python submission defines a `Solution` class, while the JavaScript submission exposes a `twoSum` function. They are intended to be run in the corresponding LeetCode environment; standalone command-line execution would require a test harness.
